## 🔐 Безопасность и конфиденциальность

⚠️ **Важно понимать:**

- VPN **не делает вас анонимным**
  - Владелец VPS видит ваш IP
  - Сайты видят IP вашего VPS (не вашего провайдера)
  - DNS запросы могут утекать (используйте VPN DNS)

- Приватный ключ **остаётся на телефоне**
  - Сервер только знает публичный ключ
  - Никогда не экспортируется или отправляется

- **Один ключ = один peer**
  - Если скопировать ключ на второй телефон, второй не сможет подключиться
  - Код привязан к первому активировавшему ключу

## Готовый сценарий

```text
/buy → выбор тарифа и принятие условий → счёт Telegram Stars
     → pre_checkout: проверка пользователя, заказа, суммы, срока счёта
     → successful_payment: подтверждённая Telegram оплата
     → транзакция: платёж + аккаунт/продление + очередь доставки
     → бот отправляет код и инструкцию
     → Android генерирует свой ключ и активирует код
     → API атомарно закрепляет код за этим публичным ключом
     → WireGuard разрешает трафик до окончания срока
```

| Тариф | Цена | Тип покупки |
|---|---:|---|
| 30 дней | 100 ⭐ | Разовая |
| 90 дней | 270 ⭐ | Разовая |
| 365 дней | 900 ⭐ | Разовая |

Нет автосписаний. «Автоматически» здесь означает проверку оплаты, выдачу кода, привязку устройства, продление и отключение по сроку. Создание бота, настройка VPS и первоначальная активация пользователем остаются необходимыми.

### Первая и повторная покупка

Первый платёж создаёт один аккаунт на Telegram ID и случайный nonce. Код доступа получается через HMAC от серверного секрета, Telegram ID и nonce, поэтому бот может повторно показать тот же код через `/access`, не сохраняя его в открытом виде в БД. API хранит хеш кода. Приватный WireGuard-ключ остаётся на Android и шифруется с помощью Android Keystore.

До первой активации покупки суммируют дни. После активации повторная покупка продлевает текущую подписку от `max(текущий срок, сейчас)`. Цена и длительность фиксируются в заказе, поэтому изменение тарифов в коде не меняет уже выданный счёт. Счёт действителен 30 минут до pre-checkout. Продление использует прежний аккаунт и код: заново активировать приложение не требуется.

## Что значит «одно устройство»

- Один аккаунт → один публичный WireGuard-ключ → один серверный peer и IP.
- Код закрепляется за **первым активировавшим его приложением**, а не просто первым получившим сообщение.
- Повторная активация другим ключом отклоняется, включая одновременную активацию на двух телефонах: используется транзакция SQLite `BEGIN IMMEDIATE`.
- `/device` запрашивает подтверждение, удаляет старый peer, сбрасывает старую сессию, меняет код и сохраняет срок. Доступно раз в 24 часа.
- Не пересылай неактивированный код: чужой телефон сможет активировать его первым. Владелец Telegram-аккаунта может отключить его через `/device`.
- Переустановка приложения/очистка данных считается сменой устройства.

**Это не аппаратная DRM-привязка и не абсолютная защита от копирования.** Извлечённый на взломанном/root-устройстве приватный ключ может использоваться другим клиентом. WireGuard не умеет надёжно отличать два физических устройства с одинаковым скопированным ключом. Приложение не предлагает экспорт ключа; IMEI и серийный номер не собираются.

## Telegram-бот

- `/start` — меню.
- `/buy` — покупка/продление и принятие условий.
- `/access` — код, срок и ссылка на APK.
- `/device` — подтверждение смены устройства.
- `/terms`, `/privacy` — ссылки на опубликованные документы.
- `/paysupport` — контакт поддержки и Telegram ID пользователя.

Бот работает через **long polling** на VPS. Не нужен публичный webhook, а пользователи не могут вызвать платёжный endpoint и заявить, что они «заплатили». События поступают непосредственно из Bot API по TLS с токеном бота.

Перед выдачей проверяются Telegram ID покупателя, ID заказа, валюта XTR, сумма и факт ранее одобренного pre-checkout. Код не выдаётся по нажатию кнопки, скриншоту или одному pre-checkout. Telegram описывает этот порядок и требует Stars для цифровых товаров внутри Telegram: [1](https://core.telegram.org/bots/payments-stars).

### Сбои и повторные события

- `payments.charge` и `payments.order_id` уникальны. Одна оплата не продлевает срок дважды даже при параллельной обработке.
- Входящие updates сохраняются в SQLite **до** продвижения Telegram offset. После перезапуска обработка продолжается.
- Платёж, доступ и задание доставки сообщения записываются одной транзакцией.
- Доставка сообщения повторяется при временной сетевой ошибке. Если бот заблокирован, состояние платежа не теряется; после разблокировки помогает `/access`.
- Сбой после фактической отправки, но до отметки в outbox может привести к повторному сообщению, **но не к повторному начислению дней**.
- Некорректный платёж не выдаёт доступ и создаёт уведомление администратору для проверки/возврата. Отозванный аккаунт не может оплатить новый счёт; редкая гонка отзыва после pre-checkout также требует проверки.
- Polling, pre-checkout, обычные события, доставка и возвраты работают в отдельных потоках. Запускается только **один процесс бота**.

Telegram не хранит необработанные updates бесконечно. При длительном простое, превышающем окно хранения Telegram, понадобится сверка с историей Stars; автоматический импорт всей истории транзакций в этой версии не реализован. Нужны мониторинг VPS, алерты и резервные копии. Если потерять БД, одной переустановкой приложения историю оплат не восстановить.

## Возвраты

Продавец рассматривает обращения через `/paysupport`. Автоматического обещания возврата по любому запросу нет: условия должны соответствовать реальным обязательствам продавца.

```bash
sudo tiho-payments list
sudo tiho-payments refund 'TELEGRAM_PAYMENT_CHARGE_ID'
# Сначала показать сумму. После проверки подтвердить:
sudo tiho-payments refund 'TELEGRAM_PAYMENT_CHARGE_ID' --confirm
sudo tiho-payments queue
```

Возврат ставится в долговечную очередь; работающий бот вызывает `refundStarPayment`, повторяет временно неудачные попытки и учитывает уже выполненный возврат. Затем идемпотентно вычитает приобретённые этим платежом дни из оставшегося доступа. Если оплаченного времени больше не осталось, peer удаляется. Частичных денежных возвратов нет: возвращается весь платёж. При нескольких покупках это вычитание дней из общего остатка, а не пропорциональный учёт уже использованного трафика.

Входящие `refunded_payment` тоже обрабатываются, в том числе если пришли до отложенного `successful_payment`. История сохраняется для проверки. Возврат неизвестного/несовпадающего платежа не применяется автоматически и требует разбора администратором.

- Android 8+, обычный WireGuard, один VPS с публичным IPv4. Обфускации нет; некоторые сети блокируют WireGuard.
- VPS-установщик только для **чистого Ubuntu 22.04/24.04** с systemd. Не применять вслепую к существующей инфраструктуре.
- Клиент направляет `0.0.0.0/0` и `::/0` в туннель. Сервер маршрутизирует только IPv4; IPv6 намеренно не выходит наружу. DNS: Cloudflare 1.1.1.1/1.0.0.1.
- Статус «Туннель включён» — локальный интерфейс, не проверка handshake. Проверяй реальный IP и `wg show`.
- Удаление просроченного peer — раз в 30 секунд. Телефон может остаться с включённым туннелем без интернета: нужно отключить его для покупки/продления и включить после.
- Самостоятельного kill switch и полноценного автоподключения после перезагрузки нет. Системная блокировка соединений без VPN на Android требует отдельного тестирования.
- API и бот в MVP работают root с ограниченными capabilities, systemd sandbox и закрытой БД. Это не замена security-аудиту; перед коммерческим запуском лучше отделить привилегированный WireGuard-агент от непривилегированных API/бота.
- Нет абсолютной анонимности или проверенного «no logs». Сохраняются Telegram ID, покупки, платёжные идентификаторы, публичные ключи, адреса и сроки. Приватные ключи телефонов в API не отправляются.
- Секрет `/etc/tiho.env` теперь нужен и для восстановления кодов. Его ротация без миграции нарушит `/access`. Не теряй его; не публикуй `.env`, БД или WireGuard-конфиги.
- Нужны нагрузочные тесты, DDoS-защита, мониторинг, бэкапы, политика хранения/удаления персональных данных и юридические документы под твой бизнес.
